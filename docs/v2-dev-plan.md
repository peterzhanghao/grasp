# 掌控 v2 开发计划（Grasp）

> 状态：待批准开工。**本文件只做计划，不含实现。** P1 已获原则批准；按用户要求先交计划，确认后再开发。
> 配套设计：[v2-design.md](v2-design.md)。命名：产品「掌控 / Grasp」，核心对象「掌控卡」，包名与数据目录不变。

## 0. 计划摘要

- 交付目标：v2.0 教练闭环（建卡 → 今天这一步 → 干预/观察 → 对比 → 修订 → 应用），v2.1 接会话证据。
- 工程策略：同一插件身份 `@local/loop-atlas` 升级到 2.0.0；分支开发；旧数据 schema v2 → v3 迁移，先备份后迁移、可回退；v1 保留 tag。
- 验证策略沿用上一轮：domain 纯函数测试 → 假宿主集成测试 → 假宿主+真实 Chromium 结构/无障碍 → 真实 Harness 实机走查（首次 10 分钟、次日回填、观察/修订）。
- 任务分解：4 个阶段（P0 已完成、P1 地基、P2 教练 UI、P3 会话证据、P4 打磨），共 20 个任务；每个任务有 ID、依赖、写入范围、验收，可直接映射成 GitHub issues 或团队任务。
- 并行方式：domain 引擎、host ops、client UI、内容教练包四条线并行；QA 独立；Lead 负责迁移、部署、实机验收与最终合并。
- 估算（相对）：P1 ≈ 2 个开发批次（可 3 线并行）；P2 ≈ 3 个批次；P3 ≈ 1.5 个批次；P4 ≈ 1 个批次 + 你真实使用一段时间。总量约 6—8 个“批次”，批次内以测试出口为界，不以日历承诺。

## 1. 范围

### v2.0 MVP 必做

1. schema v3 + v2→v3 迁移 + 旧记录只读归档 + 回退演练。
2. 纯函数引擎：缺口诊断、下一步生成、掌控卡状态机、版本与观察校验。
3. Host ops v3：掌控卡/干预/观察/版本/应用产物；HTTP 与 agent 工具适配；旧数据包导入导出兼容。
4. 掌控六问向导（可跳过、可离线、AI 追问可选），10 分钟生成第一张卡。
5. 首页「今天这一步」+ 掌控卡详情 + 观察回填/对比 + 修订 + 应用产物复制。
6. 原理库（复用 v1 内容与图谱/列表，降级为参考）。
7. 资料与权限（改名、迁移报告修复、会话证据开关占位）。
8. 全量文案改名「掌控 / Grasp」；v1 已装显示名已改（本轮完成 client 侧）。

### v2.1 必做

9. 会话摘要证据：权限、候选预览、勾选写入、删除/撤回、代理指标标注。

### 明确不做（本轮）

- 不做课程/进度条；不改 29 张内容卡的知识结构（只加“缺口→原理卡”映射与教练话术）。
- 不做自动执行用户代码、不读代码/消息正文、不联网外发。
- 不做多系统观测仪表盘、团队协作实时同步、移动端专属布局。
- 不新增插件身份/服务进程；不重写 Harness 外壳。

## 3. 任务分解（可直接建 issue / 团队任务）

约定：`写入范围` 是并行时的互斥边界；`验收` 是任务完成的硬条件。T 编号即 issue 标题前缀（如 `[T07] 掌控六问向导`）。

### P1 · 地基

**T01 数据模型 v3 与迁移（domain + host + tests）**
- 内容：定义 `loops/interventions/observations/archive` 表结构与校验器；`schemaVersion 2→3` 迁移；v2 表映射（investigations→loops、predictions→interventions/observations、experiments/tasks/notes/dialogs 关联）；无法映射记录进 `archive`；迁移幂等；迁移前备份与读回计数核对。
- 写入范围：`src/domain/schema.js`、`src/domain/migrate.js`、`src/domain/pack.js`、`src/host/storage.js`、`test/domain/**`、`test/integration/r0-migration*`。
- 验收：真实 v2 数据副本迁移后 100% 可读；逐字节备份；回退脚本可用；v3→重复迁移幂等；非法/悬空引用拒绝；测试全绿。

**T02 缺口诊断与下一步引擎（纯函数）**
- 内容：10 类缺口规则（目标不清/未测量/测得晚/动作为零/饱和/代理指标/缺反证条件/振荡/漂移/适应失败）；掌控卡状态机；「今天这一步」优先级 + 3 个时长档位 + 降级动作；模型不可用时的规则文案。
- 写入范围：`src/domain/gaps.js`、`src/domain/next-step.js`、`test/domain/**`。
- 验收：每条规则有正反用例；任意状态都生成且只生成一个 nextAction；无“空动作”分支；纯函数无 IO。

**T03 Host ops v3 与接口**
- 内容：`loop.createFromAnswers/update/pause/archive/revise`、`intervention.create/finish`、`observation.create`（强制 verdict）、`view.setActive`、`package.*` v3 兼容、迁移报告读 `state.meta` 修复；HTTP 与 agent 工具动作（读：loops/today/library；写：只允许用户操作，agent 只读 + 现有 save_note/save_prediction 兼容）。
- 写入范围：`src/host/ops.js`、`src/host/http.js`、`src/host/tools.js`、`test/integration/**`。
- 验收：全部写操作走提交队列与原子写；失败不污染内存；模型不可用时建卡不依赖 LLM；agent 不能替用户判定观察 verdict（权限断言测试）。

**T04 内容教练包（content）**
- 内容：在内容包中加入 `gapPlaybook`（10 类缺口 → 1—2 个 nodeId + 首个动作模板）、四类系统的六问话术与示例、掌控卡字段预填模板；不改 29 节点正文与来源。
- 写入范围：`data/core.json`、`locale/**`、`test/content/**`。
- 验收：内容校验通过；每个缺口映射的 nodeId 存在；四类模板都能生成问句；zh/en key 集合一致；不引入未核验主张。

**T05 改名收尾（host 文案 + 文档）**
- 内容：host 日志/系统提示词/工具描述改为「掌控」并验证一次重组合后生效；README 指向 v2 设计与计划；v1 历史文档保留旧名并注明。
- 写入范围：`src/host/**`、`README.md`、`docs/**`（不含 v1 历史报告）。
- 验收：重组合后 agent 工具描述与对话系统提示词显示「掌控」；grep 无品牌「回路」残留（控制论术语除外）。

**G1 出口**：T01—T05 全绿；迁移回退演练记录；引擎/接口/迁移集成测试通过；模型不可用路径通过。

### P2 · 教练 UI

**T06 新信息架构外壳**
- 内容：页面路由（今天/向导/掌控卡/原理库/资料与权限/设置区入口）；顶部简化；状态条；窄屏分段；空/错/只读/模型不可用状态矩阵。
- 写入范围：`src/client/App.js`、`src/client/state/**`、`src/client/views/**`、`src/client/styles/**`。
- 验收：每页唯一主行动；没有空表单；返回路径清晰；沿用宿主 token。

**T07 掌控六问向导**
- 内容：一屏一问、进度、跳过/我不知道（→缺口）、草稿按卡保存；确定性字段映射；AI 追问（最多 2 个，可关）；卡预览可编辑；Q1+Q6 即可建卡。
- 写入范围：`src/client/views/Wizard*`、`src/client/state/**`、`src/client/api.js`。
- 验收：离线/模型不可用时仍能完成建卡；跳过项转换为缺口；刷新/退出后草稿恢复。

**T08 掌控卡详情**
- 内容：一句话系统描述、状态徽标、小回路图（目标/测量/比较/动作/系统/扰动/延迟，缺口红色虚线）、缺口列表、1—2 张原理卡（含“在你这意味着什么”）、今天这一步、观察时间线、版本入口。
- 写入范围：`src/client/views/LoopCard*`、`src/client/layout/**`、`src/client/styles/**`。
- 验收：小回路图不占整页；文字优先；缺口可折叠/忽略；原理卡最多 2 张。

**T09 干预、观察与对比**
- 内容：设计一次最小检验（干预+预测+判据+窗口）；回填观察（计数/比例/时长/文本，来源标注）；强制 verdict；对比“预测 vs 实际”。
- 写入范围：`src/client/views/Observation*`、`src/client/state/**`。
- 验收：不选 verdict 不能保存；保存有宿主回执；窗口到期由首页推荐回填；观察可删除（用户显式操作）。

**T10 修订、版本与应用产物**
- 内容：卡版本 +1、变更摘要、版本对比（只显示改动字段）；验收/停止条件/人工检查点编辑与复制；关联任务。
- 写入范围：`src/client/views/Revision*`、`src/client/views/Application*`。
- 验收：旧版本可查看；改动可追溯；复制内容与卡内一致；不自动外发。

**T11 原理库**
- 内容：复用 v1 领域尺度/列表/图谱作为参考视图；按缺口过滤；原理卡详情；返回当前卡。
- 写入范围：`src/client/views/Library*`、`src/client/views/DomainScale*`（迁移改造）。
- 验收：不再作为首页；从卡内可直接跳到相关原理卡并返回；搜索可用。

**T12 资料与权限**
- 内容：改名；数据路径/备份/导出/导入/迁移报告（读 state.meta 修复 P2）；会话证据开关占位（禁用并说明 v2.1 提供）。
- 写入范围：`src/client/views/Resources*`、`locale/**`。
- 验收：迁移报告重启后仍正确；导入预览/冲突/幂等不回退；会话证据开关默认关闭且说明清楚。

**T13 可访问性、响应式与状态文案**
- 内容：键盘可达/焦点归还/Escape；1024/窄屏/200%；浅深色对比；状态文案矩阵（空、只读、模型不可用、保存失败、导入冲突）。
- 写入范围：`src/client/styles/**`、`src/client/**`（仅无障碍属性）。
- 验收：扩展现有 browser-check；结构断言 + 真实应用抽查；无 i18n key 泄漏。

**G2 出口**：T06—T13 完成；首次 10 分钟实测（人工走查脚本）；任意状态有主行动（自动枚举）；模型不可用路径可用；键盘/窄屏/浅深色通过；一次真实 Harness 走查记录。

### P3 · 会话证据

**T14 会话摘要 provider（host，只读）**
- 内容：读取范围白名单（会话标题/时间/轮次/模型、工具调用计数、错误/重试/取消计数、首次成功时间、上下文用量）；禁止消息正文/代码/文件路径/工具参数；使用宿主会话投影/查询服务（实现前先核对当前运行时 API）；同意状态存储；内存 TTL。
- 写入范围：`src/host/evidence.js`、`src/host/ops.js`、`test/integration/**`。
- 验收：字段白名单测试（越权字段不出现）；未同意时调用直接返回不可用；不联网。

**T15 证据候选与写入/撤回 UI**
- 内容：生成候选清单（指标、时间范围、来源会话、计算方式可展开）；勾选写入观察；标注“代理指标”；删除单条/一键清空；关闭开关后不再产生候选。
- 写入范围：`src/client/views/EvidenceCandidates*`、`src/client/state/**`、`src/host/ops.js`。
- 验收：不勾选不写入；删除后教练不再引用；关闭后候选为空；测试覆盖。

**T16 权限文案与审计**
- 内容：权限页说明、同意记录（时间/范围）、审计清单；错误与撤回说明。
- 写入范围：`locale/**`、`src/client/views/Permission*`、`docs/acceptance.md`（新增章节）。
- 验收：文案与实际读取范围一致；撤销可验证；不夸大能力。

**G3 出口**：T14—T16；无越权读取；删除/撤回有效；报告写明代理指标与因果边界。

### P4 · 打磨与验收

**T17 真实使用两周**：按 S3/S4 记录（每天/隔天一条观察、至少 3 张卡、一次修订），只修阻塞问题。
**T18 实机视觉验收**：浅/深、1024/窄屏/200%、弹层、空/错状态截图；与结构证据分开标注。
**T19 文档与交付**：README、v2 报告、acceptance 更新、迁移与回退手册、证据索引。
**T20 发布与回退演练**：真实数据迁移（备份→迁移→读回核对）、v1 tag、回退流程演练、版本 2.0.0。
**G4 出口**：S1—S4；回退可用；交付报告如实列未验证项。

## 4. 并行、写入边界与协作

| 角色 | 负责 | 互斥写入范围 |

规则：
- 同一时间只有一个组写 `src/host/**`（host 组与 Lead 协调）；`client.js` 只由 client 组构建。
- 契约变更先改 `docs/v2-design.md`，再动代码。
- 共享任务看板：T01—T20 建为团队任务，标明依赖（T01/T02/T03 可并行；T06 依赖 T01/T02/T03 接口；T14 依赖 T01；T15 依赖 T14）。
- 每批结束写“上一批错在哪 + 实际验证”，并入 v2 报告。

## 5. 分支、版本与部署

- 分支：`feat/v2-grasp`（从 `main` 或当前 HEAD 切出）；v1.0.0 打 tag `v1.0.0-loop-atlas` 保留回退。
- 版本：`package.json` 升 `2.0.0`；包名/路由前缀/数据目录/agent 工具名不变。
- 部署：Host 改动需插件页关/开触发重组合；Client 改动由 client-HMR 热替换；每批部署后实机走查。
- 数据：开发期全部用临时目录副本；**只有 G4 验收通过后才对真实数据执行 v3 迁移**（迁移前自动备份，按 T01 流程）；迁移失败降级只读、不覆盖。
- 回退：恢复 v1 源码 tag + 恢复迁移前备份数据；插件页关/开重组合。

## 6. 测试与验收矩阵

| 层 | 内容 | 出口 |
| --- | --- | --- |
| domain 单测 | 缺口规则、next-step、状态机、迁移、包校验 | 每条规则正反例；确定性 |
| integration | fake-ctx + 真实 HTTP：ops、迁移、失败注入、权限断言 | 契约全绿；失败可重试 |
| harness | fake-llm 成功/失败/abort/慢流；会话证据 fixture | 覆盖模型不可用与异常 |
| browser-check | 假宿主 + 真实 Chromium：新 IA、键盘、窄屏、200%、浅深色 | 结构断言全绿 |
| 实机 | 首次 10 分钟（人工脚本）、真实模型对话、观察/修订、迁移后重开 | S1—S4 证据 |
| 数据安全 | 备份逐字节、迁移回退、只读降级、导入冲突/幂等 | 每次发布前演练 |

行为化验收（沿用设计 §15）：S1 首次 10 分钟出卡；S2 任意状态唯一主行动；S3 次日 ≤5 分钟回填；S4 30 天 3 卡 ≥1 修订（真实使用，不拿自测冒充）。

## 7. 风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 教练退化成表单 | 回到“没头绪” | 每问可跳过；Q1+Q6 可建卡；每页唯一 CTA；G2 人工走查 |
| 诊断幻觉 | 错误建议 | 规则优先；模型只措辞；输出必须引用字段；用户可忽略 |
| 迁移丢数据 | 不可接受 | 备份→演练→读回核对→archive 兜底→回退 |
| 会话证据越权 | 隐私事故 | 默认关闭；白名单字段；两段式勾选；删除/撤回；测试断言 |
| UI 改动过大导致回归 | 交付延迟 | 复用 v1 原理库组件；每批 browser-check；v1 tag 可回退 |
| 真实模型慢/不可用 | 首体验差 | 规则路径可建卡；生成中状态与停止；提示宿主降低 reasoning effort |
| 并行写冲突 | 返工 | 互斥写入范围 + 任务依赖 + Lead 合并前跑全量 |

## 8. 第一周（确认开工后）的执行顺序
