## 1. 产品定义

**一句话**：掌控是一个带着你修回路的教练——把你正在试图控制的某个真实系统画成一条回路，找出它缺的那一环，做一次小干预，用观察去修正你的解释。

**目标用户**：正在用 AI 智能体/工程项目工作、希望把控制论真正用在手上系统的人（当前就是本 Harness 的用户）。

**要解决的两个原话问题**：
1. “没有头绪，缺少指引” → 首页只有一个主行动，永远知道下一步；首次 10 分钟出一张卡。
2. “不能满足学习并应用控制论” → 学习发生在修回路的过程中：原理卡按缺口出现，应用产物直接来自你的系统并回填观察。

**非目标**：
- 不做一套完整控制论课程（原理库是参考，不是课表）。
- 不做知识图谱浏览器（图谱降级为原理库的一个视图）。
- 不做真实系统辨识/自动执行你的代码；插件不申请 shell/文件写入/外发。
- 不宣称“用了就掌握”；记录状态不等于掌握状态。

**成功指标（行为化，替代“功能齐不齐”）**：
- S1 首次使用者 10 分钟内独立完成一张掌控卡，并能说出下一次要看什么。
- S2 任意时刻打开面板，100% 有一个明确的主行动（没有“空表单”页）。
- S3 第二天回来能 ≤5 分钟回填一条观察。
- S4 30 天内 ≥3 张掌控卡、≥1 次修订（真实使用记录，不靠自测）。
- S5 会话证据只在用户勾选后写入；删除后不再出现在任何建议里。

## 2. 核心对象：掌控卡（Loop Card）

一张卡 = 一个你正在试图控制的系统。字段按“教练会问到的”设计，不按字段齐全设计。

```
Loop {
  id, title, systemType: 'coding-agent'|'product'|'team'|'personal'|'custom',
  summary,                       // 一句话：这个系统是什么
  goal: { quantity, criterion, current },   // 目标量 / 可判定判据 / 当前值
  measurement: { how, cadence, source: 'manual'|'session'|'experiment', confidence },
  action: { levers: [], cannot: [] },       // 你能改的 / 改不了的
  disturbances: [ { text } ],
  delays: [ { from, to, estimateSeconds|null, unknown } ],
  boundary: { nonGoals: [], notes },        // 边界/非目标
  hypothesis: { claim, counter, falsifier },// 你的解释 / 相反解释 / 什么观察会让你改口
  gaps: [ Gap ],                            // 见 §5，诊断结果
  principleRefs: [ { nodeId, userTranslation, whyHere } ], // 1—3 张原理卡
  status: 'draft'|'modeled'|'testing'|'reviewing'|'revised'|'paused'|'archived',
  nextAction: { type:'answer'|'observe'|'intervene'|'revise'|'measure'|'pause', text, estimateMin, dueAt|null },
  nextCheck: { criterion, predicted, windowStart, windowEnd, interventionId|null } | null,
  application: { acceptance: [], stopConditions: [], checkpoints: [], taskIds: [] },
  version, versions: [ { version, at, changeSummary, snapshot } ],
  legacy: false, createdAt, updatedAt, lastOpenedAt
}
```

关联表：

```
Intervention { id, loopId, action, predicted, windowStart, windowEnd, status:'planned'|'running'|'done'|'abandoned', at }
Observation { id, loopId, interventionId|null, at, source:'manual'|'experiment'|'session-evidence',
              metric: { kind:'count'|'ratio'|'duration'|'text', value, unit },
              compare: { prediction, verdict:'supported'|'refuted'|'inconclusive', reason },
              evidenceRefs: [], noteIds: [] }
```

笔记、对话、实验、任务都保留，但都**挂到掌控卡**上；首页不再单独露出它们。

**状态机**（教练依据它决定“今天这一步”）：

```
draft ──六问完成──▶ modeled ──设计检验──▶ testing ──回填观察──▶ reviewing
  ▲                    │                    │                    │
  └──补问答────────────┘                    └──暂停/放弃──▶ paused ──重启──▶ modeled
                                                                    │
reviewing ──修订出新版本──▶ revised ──设计下一次──▶ testing
```

## 3. 信息架构与页面

首页 = **今天**：

```
┌ 掌控 · 一句话副标题                                      ┐
│ 【今天这一步】一张卡：状态、要做什么、预计几分钟、主按钮   │
│ 我的掌控卡（进行中/已暂停）                                │
│ 新开一张掌控卡（唯一的次要入口）                           │
│ 原理库 · 资料与权限                         （低权重入口） │
└───────────────────────────────────────────────────────────┘
```

页面清单（每页唯一主行动）：

| 页面 | 主行动 | 说明 |
| --- | --- | --- |
| 今天（首页） | 继续/开始当前这一步 | 无卡时主行动=新开一张掌控卡；有卡时=下一步 |
| 六问向导 | 回答当前这一问 | 一屏一问，可“我不知道”，可随时暂停存草稿 |
| 掌控卡详情 | 按状态给一个动作 | 左：小回路图（缺口红色虚线）；右：今天这一步、缺口、原理卡、观察时间线、版本 |
| 回填观察 | 保存一条观察 | 5 分钟表单；三种输入：计数/比例/时长 + 一句文本 |
| 修订卡 | 保存新版本 | 只改需要改的字段，自动生成版本摘要 |
| 原理库 | 搜索/按缺口筛选概念 | 复用现有 29 张内容卡 + 图谱/列表视图（降级为参考） |
| 资料与权限 | 备份/导出/导入/迁移报告/会话证据开关 | 原“资料与备份”扩展 |
| 设置区入口 | 打开掌控 | 保留 `settings.section`，文案改名 |

不做的页面：节点长档案、独立的预测列表、独立的任务契约弹窗、图谱当首页。

## 4. 首次体验：掌控六问（完整脚本）

一屏一问，顶部进度 1/6；每问都有“我不知道/跳过”，跳过会变成待测量缺口而不是报错；可随时退出，草稿自动存。

**Q1 目标**：「你在试图让什么保持不变或变好？」
- 提示：最好是一个能被判定的量或状态（例：改动提交前稳定通过测试且无回归；发布后 24h 无回滚）。
- 追问（答不上来）：给 2 个示例选项 + “我自己写”。
- 不确定 → 缺口 `unclear-goal`。

**Q2 测量**：「你现在靠什么知道它好还是不好？」
- 提示：测试、日志、评审、用户反馈、感觉都算，但要写清多久看一次。
- “靠感觉/没测” → 缺口 `unmeasured`。

**Q3 动作**：「你能直接改变什么？又改不了什么？」
- 提示：权限、工具、时间、人手、发布开关。
- 没有可改动作 → 缺口 `authority-gap`；边界据此生成。

**Q4 扰动**：「哪些外来的变化会让它偏离？」
- 提示：需求变更、flaky 测试、模型波动、上游依赖、并发、人的注意力。
- 允许空着（教练会建议先观察一天）。

**Q5 延迟**：「从你动手，到你能看见结果，大概多久？」
- 提示：分钟/小时/天；“不知道”也记下。
- 未知或明显长于你的检查周期 → 缺口 `late-measurement`。

**Q6 解释**：「你现在的解释是什么？什么观察会让你改口？」
- 提示：两句都要——主张 + 会推翻它的观察。
- 没有推翻条件 → 缺口 `missing-counter-signal`。

**AI 追问（最多 2 个，可关）**：从“代价 / 相反解释 / 边界”里挑最缺的一个。模型不可用时跳过，只做规则诊断。

**生成掌控卡**：确定性映射字段 → 规则诊断缺口 → 模型把缺口与原理卡写成“在你这意味着什么 + 可以做什么”（结构化 JSON，字段校验失败则回退规则文案）。用户在卡上可改任意字段。

**完成条件**：Q1 与 Q6 有内容即可“先建卡再补”，不强迫六问全填。

## 5. 缺口诊断与原理卡映射

诊断以**确定性规则**为主（可解释、可测试），模型只负责措辞与追问。

| 缺口 | 判定规则（来自六问/观察） | 优先原理卡（1—2 张，取现内容卡） | 建议的第一个小动作 |
| --- | --- | --- | --- |
| `unclear-goal` | goal.criterion 空或不可判定 | goal, boundary | 把目标改写成“可判定的一句话” |
| `unmeasured` | measurement 空或“靠感觉” | measurement, blackbox | 定义最小测量：一个数字或一条日志 |
| `late-measurement` | 延迟未知，或延迟 > 检查周期 | delay, sampling | 缩小一次改动/加快一次反馈 |
| `authority-gap` | action.levers 为空 | actuator, variety | 找最小可改点或换可控部分 |
| `saturated` | 观察显示动作顶到上限 | actuator, pi | 降增益、换动作、等恢复 |
| `proxy` | 单一指标被当目标 | indicator, positive | 加一个独立指标并写会冲突的判断 |
| `missing-counter-signal` | hypothesis.falsifier 空 | positive, secondorder | 写一条会证伪的观察 |
| `oscillating` | 观察：来回摆动/反复回滚 | stability, delay, pi | 降增益/加阻尼/减少延迟 |
| `drift` | 观察：稳定但不在目标 | pi, measurement | 修测量或加记忆项 |
| `adaptation-failure` | 同一动作反复失败 | adaptation, model | 换规则而不是加力 |

显示规则：每次最多 3 个缺口、最多 2 张原理卡；每张卡必须包含「在你这意味着什么」+「你现在可以做的一个动作」+ 来源核验档位；用户可折叠/忽略，忽略的缺口不再重复推荐（除非观察变化）。

## 6. 「今天这一步」生成规则

输入：卡状态 + 最近观察 + 到期时间 + 上次打开时间；输出一个动作，永远只有一个主按钮。

| 优先级 | 条件 | 动作 | 预计 |
| --- | --- | --- | --- |
| 1 | status=draft | 继续六问（从第一个空问题开始） | 3—5 分钟 |
| 2 | testing 且窗口已到期且无观察 | 回填这次观察 | 5 分钟 |
| 3 | testing 且未到期 | 等待，但给“提前看一次/延长窗口” | 2 分钟 |
| 4 | modeled 且无 nextCheck | 设计一次最小检验（小干预 + 预测 + 判据） | 30 分钟 |
| 5 | reviewing | 对比观察与预测，决定是否修订 | 15 分钟 |
| 6 | revised | 设计下一次检验 | 10 分钟 |
| 7 | paused | 一句话重启，或归档 | 3 分钟 |
| 8 | 任意状态且用户只有 5 分钟 | 只做最小动作（记录一条观察/改一句判据） | 5 分钟 |

硬规则：
- 任意页面主按钮只有一个；次级动作收在“其他”。
- 没有“请填写”的空页；每个空状态都给一个具体动作或示例。
- 模型不可用时，“今天这一步”仍由规则生成。

## 7. 观察、对比与修订

**回填观察（≤5 分钟）**：时间（默认现在）→ 来源（手动/实验/会话证据）→ 指标类型与值 → 与预测比较（支持/反驳/不足）→ 一句解释（可选）→ 关联笔记（可选）。

**对比**：系统展示“你当时预测 → 实际”的并列，并强制选一个 verdict；不判定也不允许保存（避免“看起来像证据”）。

**修订**：卡片版本 +1，记录 changeSummary；版本时间线可看任意旧版本；旧观察永远保留（不随卡删除，除非用户显式清空整卡）。

## 8. 应用产物（不再是表单）

掌控卡详情里固定三块，随卡版本保存：
- **验收**：什么证据算够（可复制到任务）
- **停止条件**：什么时候停/回退
- **人工检查点**：谁在哪个位置拦一下
以及关联任务（可复制给 agent 的简短任务说明）。所有产物都是“可复制文本”，插件不自动发送任何地方。

## 9. 真实证据：Harness 会话摘要（v2.1）

**默认关闭**。开关在“资料与权限”，开启时展示数据清单与用途，用户确认才生效。

允许读取的字段（只读、本地、不外发）：

| 字段 | 用途 | 备注 |
| --- | --- | --- |
| 会话标题/开始结束时间/时长/轮次/模型 | 定位证据来源 | 标题可能含用户命名，可关闭 |
| 工具调用次数（按工具名）、失败/错误次数、重试次数、取消次数 | 回路指标（重试率/失败模式） | 不读参数 |
| 首次成功时间、任务完成/中断 | time-to-green、完成率 | 有投影才用 |
| 上下文压力/用量 | 延迟与饱和的代理指标 | 有则用 |

**禁止**：消息正文、代码与文件内容、文件路径、工具参数、凭据、其他 profile 数据。

流程（两段式）：点“从我的会话找证据”→ 生成候选清单（每条含指标、时间范围、来源会话标题、计算方式，可展开）→ 用户勾选 → 才写入观察（标 `source:session-evidence` 与“代理指标，只能说明发生过什么”）→ 可删除。

撤回：关闭开关后不再读取；已写入证据可逐条删除或一键清空；删除后教练不再引用。摘要缓存可配 TTL，默认只在内存。

## 10. 四类系统模板

同一“六问”内核 + 模板化措辞/示例/原理卡映射：

| 模板 | v2.0 | 差异 |
| --- | --- | --- |
| coding agent | 完整（含会话证据） | 目标量/测量/延迟默认围绕测试、评审、time-to-green |
| 产品/项目 | 通用（占位） | 默认指标：回滚、发布节奏、验收争议 |
| 团队 | 通用（占位） | 默认指标：协调失败、指标替代目的、责任落点 |
| 个人 | 通用（占位） | 默认指标：学习回路、注意力、决策偏差 |

占位不等于残废：六问与诊断通用可用，只是没有定制示例与专用证据源。

## 11. 数据模型 v3 与迁移

`state.schemaVersion` 2 → **3**。新增 `loops`、`interventions`、`observations`、`archive`（旧记录只读快照）；保留 `notes/revisions/dialogs/experiments/tasks/importLog/meta`；`view` 改为首页导航状态。

**v2→v3 迁移映射（不丢数据）**：

| v2 | v3 |
| --- | --- |
| investigations | loops（subject→summary 参考；claim→hypothesis.claim；counter→hypothesis.counter；nextTest→nextAction；status 映射） |
| predictions（open） | interventions（predicted=text；status='planned'，关联 loop） |
| predictions（已解决） | observations（compare.verdict 映射） |
| experiments | 保留原表；有 subject 的生成 observations（source=experiment）并关联 loop |
| tasks | loops.application 关联 + 保留 tasks 表 |
| notes / revisions | 保留；subject 增加 `loop`；旧的 investigation 引用经映射表改到 loop |
| dialogs | 保留；subject 增加 `loop` |
| relations（个人批注） | 保留，作为原理卡的个人批注 |
| 无法映射的旧记录 | 进 `archive`（只读、可导出），绝不丢弃 |

迁移执行沿用 v1→v2 的纪律：先只读备份 → 隔离目录演练 → 迁移后读回计数核对 → 失败降级只读不覆盖 → 保留回退入口。

## 13. 交互与视觉约束（在 v1 基础上加）

- 首页一屏一主 CTA；所有页面主行动不超过 1 个。
- 回路图是一个**小部件**（约 1/3 宽），不是整页画布；文字优先于几何。
- 正文字号 ≥16px、行高 1.7、正文宽度 34—42 汉字；标签 ≥12px；延续宿主 `--dsw-alias-*` token，浅深色自动。
- 键盘：所有按钮/卡可 Tab，Enter/Space 激活，Escape 关闭弹层并归还焦点；不依赖鼠标 hover 才能发现操作。
- 状态：空/只读/模型不可用/保存失败各有明确文案与一个可执行动作；回执只来自宿主持久写成功。
- 动效只用于“等待模型/保存/状态变化”，尊重减少动态。

## 15. 验收（行为化）

1. 首次使用（新用户，不看文档）10 分钟内完成一张卡，并能说出“下次看什么”。
2. 任意状态打开页面都有唯一主行动（自动化枚举状态断言）。
3. 第二天 ≤5 分钟回填一条观察（真实使用记录）。
4. 旧 v2 数据 100% 可读、可回退；迁移前备份逐字节一致。
5. 模型不可用时仍能建卡、回填、看下一步（规则路径）。
6. 会话证据必须勾选才写入；删除后不再出现在任何建议/文案里（集成测试）。
7. 键盘/窄屏/浅深色/200% 不退化（扩展现有 browser-check）。

## 16. 风险与反模式

| 风险 | 对策 |
| --- | --- |
| 教练退化成表单 | 每问可跳过；首页永远给“5 分钟版本”；完成门槛低（Q1+Q6 即可建卡） |
| 诊断幻觉 | 规则优先；模型输出必须引用字段；用户可编辑/忽略 |
| 代理指标当因果 | 一律标注“代理指标”；观察必须选 verdict 才能保存 |
| 又变回知识地图 | 原理库入口低权重；首页不出现图谱 |
| 会话证据变监控 | 默认关闭、最小字段、可预览/删除、本地不外发 |
| 改名造成混乱 | 包/数据/路由/工具名不变；只改显示名与文案 |
| 迁移丢数据 | 备份→演练→读回核对→archive 兜底→回退入口 |
